# 09 — Transport & Gate Safety

**Depends on:** 02, 04. **The emotional parent buy, and now a legal requirement.**

CBSE pushes GPS and CCTV in school buses; Maharashtra, UP and others mandate
GPS, CCTV, panic buttons, seat belts, digital boarding records and
parent-visible live tracking.

---

## 1. Routes, stops, vehicles

```
GET/POST/PATCH /v1/transport/vehicles
GET/POST/PATCH /v1/transport/routes
GET/POST       /v1/transport/routes/:id/stops
POST           /v1/transport/allocations       student → route + stops
GET            /v1/transport/compliance        expiry dashboard
```

Distance-based `feeSlabPaise` on `route_stops` links to the transport fee head,
so allocating a student to a stop automatically prices their transport fee.

## 2. Live tracking — the architecture decision that matters

```
POST /v1/transport/pings          driver app or GPS device, batched
GET  /v1/transport/live?routeId=  current positions
WS   /ws/transport/:routeId       parent subscription
```

```jsonc
POST /v1/transport/pings
{ "vehicleId": "uuid", "tripId": "uuid",
  "pings": [ { "at": "2026-08-10T02:31:00Z", "lat": "28.7041",
               "lng": "77.1025", "speedKmph": 34 } ] }
```

**Live position lives in Redis, not Postgres.**

```
Redis:  bus:live:{vehicleId} → { lat, lng, speed, heading, at }  TTL 5 min
Postgres: batch-insert into vehicle_pings every 30s, for replay only
Retention: 7 days, partitioned by day, pruned by DROP PARTITION — never DELETE
WebSocket broadcast: at most once per 15 seconds per vehicle, regardless of
                     ping rate
```

Writing every ping straight into the OLTP database would destroy a 2-core box.
**This separation is the single most important decision in the module.**

The live map for a school with 20 buses is **ONE Redis read**, not 20 DB queries.

## 3. Boarding logs

```
POST /v1/transport/trips                 start a trip
POST /v1/transport/trips/:id/boarding    scan events, batched, offline-capable
POST /v1/transport/trips/:id/end
GET  /v1/transport/boarding?studentId=&from=
```

```jsonc
POST /v1/transport/trips/:id/boarding
X-Client-Mutation-Id: uuid
{ "events": [
  { "studentId": "uuid", "stopId": "uuid", "event": "boarded",
    "at": "2026-08-10T02:38:00Z", "scanMethod": "rfid",
    "lat": "28.70", "lng": "77.10" } ] }
```

Parent push within 3 seconds of the scan. **Buses lose signal constantly** —
offline queue with idempotent replay is mandatory, not optional.

`no_show` events matter: a child who didn't board is the alert a parent needs
most.

## 4. SOS

```
POST /v1/transport/trips/:id/sos     { type, note }
```
Priority `critical` — **bypasses quiet hours**. Notifies school admin, transport
in-charge and principal simultaneously. Sets `trips.sosRaisedAt`. In the driver
app, requires a **3-second hold** so it cannot fire from a pocket.

## 5. Gate & visitor (`modules/safety/`)

```
GET/POST  /v1/gate/visitors
POST      /v1/gate/visitors/:id/checkout
POST      /v1/gate/visitors/pre-register     → QR code
GET       /v1/gate/inside                    who is currently on premises
POST      /v1/gate/passes                    late arrival / early exit
```

Visitor capture: photo, ID type + **last 4 only** (never a full ID number), host
staff, purpose, badge number. Host approval before entry — the thing a paper
register cannot do. Blacklist auto-checked on phone match.

`GET /gate/inside` uses `visitors_inside_idx (branch_id, check_out_at)`. One query.

Gate passes write back to the student's attendance record.

## 6. Student handover — the real differentiator

Nobody does this well. It is the school's nightmare scenario.

```
GET  /v1/pickup/authorised?studentId=
POST /v1/pickup/authorised                  parent adds a person
DELETE /v1/pickup/authorised/:id
POST /v1/pickup/otp                         parent generates a one-time code
POST /v1/pickup/verify                      guard scans/enters
POST /v1/pickup/handover                    record the release
```

**`POST /pickup/verify`** returns what the guard needs to match a *face*:
```jsonc
{ "authorised": true,
  "person": { "name": "Rajesh Sharma", "relation": "father",
              "photoUrl": "https://...200px", "idLast4": "4821" },
  "student": { "name": "Aarav Sharma", "class": "5-A",
               "photoUrl": "https://..." },
  "validUntil": "2026-08-10T12:00:00Z" }
```

- **Photo is mandatory** on every authorised person. A guard matches a face, not
  a name.
- One-time OTP for ad-hoc pickups, generated by the parent in-app, expiring in
  2 hours.
- `pickup.handover.override` requires a typed reason ≥ 20 chars **and alerts the
  principal immediately**. Overrides must be rare and visible.
- Parent notified on every handover.

## 7. Compliance alerts

Scheduled job (06:00) checks vehicle insurance, fitness, permit, PUC, and driver
licence + police verification expiry. Alerts at 30 / 15 / 7 days and produces
the compliance dashboard. Overdue rows get a `red/500` left border in the UI.

---

## Acceptance criteria

- [ ] 20 buses pinging every 10s does not meaningfully increase DB write load
- [ ] Live map served entirely from Redis, one read
- [ ] WebSocket broadcast throttled to 15s
- [ ] Boarding scan works offline and replays exactly once
- [ ] Boarding scan → parent push in < 3 seconds
- [ ] SOS bypasses quiet hours and requires a 3-second hold in the app
- [ ] Pickup override requires a reason and alerts the principal
- [ ] Parents see only their own child's bus and pickup records
- [ ] `vehicle_pings` older than 7 days removed via partition drop, not DELETE
- [ ] Full ID numbers never stored for visitors
